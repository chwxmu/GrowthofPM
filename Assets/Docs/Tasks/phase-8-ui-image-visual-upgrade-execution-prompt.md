## 本次任务目标

本次只执行 `Phase 8：图片导入与 UI 视觉升级`，目标是在不破坏稳定基线的前提下，导入用户提供的图片资源，升级关键界面的视觉表现，让项目更像完成度较高的正式作品。

你要优先完成以下五包任务：

1. 清点并规范导入用户提供的图片资源
2. 冻结图片用途映射与整体视觉方向
3. 优先升级最常展示的核心界面
4. 收口图片替换后的一致性、可读性与交互安全性
5. 完成回归验证并整理升级后的截图材料

## 严格执行约束

- 不新增剧情、小游戏、统计系统、设置系统或新的复杂玩法。
- 不重写 `GameManager`、`StoryManager`、`UIManager` 等主架构。
- 不把本阶段扩成“全项目 UI 重做”或“重新做一套美术规范”的开放式工程。
- 静态 UI 修改优先在 `MenuScene` / `GameScene` 的 `Hierarchy / Inspector` 中完成；不要为了固定背景图去额外发明复杂运行时代码。
- 只有在确实需要运行时按地点切图时，才允许复用或补最小必要的 `Resources` 背景映射。
- 所有中文 TMP 文本仍统一使用 `Assets/Fonts/SIMSUN SDF.asset`。
- 不使用带固化中文文字的位图直接替换按钮文本、标题文本或说明文本。
- 不导入来源不明、用途不明、会引起版权风险的外部图片。
- 不破坏现有 `83` 个自动化测试；任何界面改动后都必须保证旧测试继续通过。

## 推荐实施顺序

### 第一包：图片资源盘点与导入设置统一

1. 先检查用户已经导入了哪些图片，不要先动界面。
2. 为每张图片建立用途判断：
   - 背景图
   - 面板底图
   - 按钮底图
   - 装饰图
   - 图标/插画
3. 统一导入设置：
   - `Texture Type = Sprite (2D and UI)`
   - 透明图保留 Alpha
   - `Wrap Mode = Clamp`
   - UI 资源优先 `Full Rect`
   - 面板/按钮资源按需切 `9-slice`
4. 把需要运行时读取的对话背景放到：
   - `Assets/Resources/Backgrounds/Dialogue/`
   - `Assets/Resources/Backgrounds/Locations/`

### 第二包：视觉方向与映射表冻结

1. 在真正替换前，先决定整体风格：
   - 企业项目管理 / 轻科技感 / 稳定蓝灰系 / 有展示质感
2. 先列出“哪张图用在哪个面板”，至少覆盖：
   - `MenuScene`
   - `DialoguePanel`
   - `DecisionPanel`
   - `TransitionPanel`
   - `EndingPanel`
   - `GameSummaryPanel`
3. 不要为了把所有图都用上而硬塞到界面里；允许只使用最合适的一部分。

### 第三包：核心界面优先升级

优先顺序：

1. `MenuScene`
2. `DialoguePanel`
3. `DecisionPanel`
4. `TransitionPanel`
5. `EndingPanel`
6. `GameSummaryPanel`
7. `CPMGamePanel`
8. `RiskDashboardPanel`

重点做：

1. 背景图与内容底板的层次关系
2. 按钮底图与按钮文案的可读性
3. 标题区、正文区、反馈区、按钮区的视觉主次
4. 对话背景图与地点切换的匹配感

### 第四包：一致性与交互安全性收口

1. 检查图片替换后是否出现：
   - 文本不清楚
   - 图像拉伸变形
   - 按钮交互区被遮挡
   - 装饰图盖住反馈文本或滚动区
2. 背景过于复杂时，优先增加半透明遮罩或信息底板，而不是降低文字字号。
3. 若图片资源不足，允许保留局部纯色区域，但要保证整体统一，不要半成品感过强。

### 第五包：验证与交付

1. 重新执行并确认：
   - EditMode 全量测试
   - Unity MCP 编译
   - Unity 控制台无新的项目级 `error`
2. 手工复核：
   - `主菜单 -> 新游戏`
   - `主菜单 -> 继续游戏`
   - `P2 -> P3 -> GameSummaryPanel`
   - `GameSummaryPanel -> 重新开始 / 返回主菜单`
   - `DialoguePanel` 背景切换
   - `DecisionPanel` AI 建议展开与选项布局
3. 至少整理一套升级后的截图，用于之后继续答辩展示或论文插图。

## 实现要求

### 关于代码改动

- 优先通过场景静态引用、Inspector 换图、9-slice 与遮罩完成视觉升级。
- 只有在必须支持运行时切换图片时，才允许做最小必要代码改动。
- 若需要代码改动，优先做：
  - 默认图兜底
  - 地点关键词到 Sprite 的映射补齐
  - 图片缺失时回退纯色背景

### 关于视觉表现

- 追求“完整、清晰、有设计感”，不是“贴图越多越好”。
- 保持项目经理模拟游戏的专业感，不要做成过度夸张或主题混乱的拼贴界面。
- 背景图服务于氛围，文本和按钮服务于可用性；若两者冲突，优先保留可用性。

### 关于图片选择

- 优先使用：
  - 无文字或少文字
  - 纹理清楚但不喧宾夺主
  - 可裁切、可九宫格、适合 UI 比例的图片
- 不优先使用：
  - 信息量过高的海报式图片
  - 强透视、强人物特写、会压住文字的复杂插画
  - 颜色与现有界面完全冲突的资源
