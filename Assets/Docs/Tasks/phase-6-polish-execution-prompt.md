## 实现要求

### 关于修复策略

- 先修“会挡住答辩”的问题，再修“看起来还能更好”的问题。
- 每个问题尽量做最小修复，不把单点修正扩成结构性重构。
- 若布局问题可以通过场景静态节点调整解决，优先改场景，不优先改复杂运行时代码。

### 关于动画与 polish

- `DOTween` 只做轻量增强，不做复杂时间线编排。
- 不追求每个面板都有动画，优先补答辩最常看到的几个页面。

### 关于测试

- 每个修复都要考虑是否需要补一个最小测试。
- 对明确的布局 / 恢复 / 面板锚点逻辑，优先补 EditMode 断言防回归。
