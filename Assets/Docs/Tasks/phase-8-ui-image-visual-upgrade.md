# Phase 8：图片导入与 UI 视觉升级

## 前置条件

- `Phase 7` 已完成，当前项目已具备稳定候选基线，详见：
  - `Assets/Docs/TaskReports/20260406/20260406_Phase7答辩封版与论文支撑收口.md`
- 当前主流程基线为：`MenuScene -> P1 -> P2 -> P3 -> GameSummaryPanel`
- 当前自动化基线为：`83 passed / 0 failed / 0 skipped`
- 当前主要问题不再是流程阻塞，而是界面材质、背景、按钮和装饰图仍偏“纯色程序风”，视觉说服力不足。

## 阶段定位

本阶段不是继续扩玩法，也不是重做整套 UI 架构，而是在现有稳定基线上，通过导入图片资源和低风险静态视觉升级，让游戏界面从“能用”提升到“更像完整作品、更适合展示”。

## 本阶段目标

围绕“导入图片资源、提升界面氛围、保持主流程稳定”完成下一轮轻量视觉升级。

优先级顺序：

1. 导入并整理图片资源
2. 建立统一的视觉映射与使用规则
3. 优先升级最常展示的核心界面
4. 保证文本可读性、按钮可点性和分辨率稳定性
5. 完成回归验证并输出新的视觉材料

## 非目标（本阶段不要做）

- 不新增剧情、小游戏、统计系统或新的 Manager。
- 不把本阶段扩成“全项目 UI 重做”。
- 不重写 `GameManager`、`StoryManager`、`UIManager`、`AIAdvisor` 主架构。
- 不为了贴图效果强行引入新 Shader、后处理链或第三方 UI 框架。
- 不使用带固定中文文案的位图按钮替代可本地化文本。
- 不因为视觉优化破坏现有 `83` 个测试基线与主流程可演示性。

## 推荐资源结构

执行时建议按用途整理图片，而不是把所有图片随意堆到一个目录：

1. 用户提供的原始资源：
   - `Assets/Art/UI/Imported/Raw/`
2. 处理后可直接用于固定 UI 的 Sprite：
   - `Assets/Art/UI/Imported/Processed/`
3. 需要运行时按地点自动加载的对话背景：
   - `Assets/Resources/Backgrounds/Dialogue/`
   - `Assets/Resources/Backgrounds/Locations/`
4. 若只是场景里固定绑定的装饰图、边框图、标题图，不必放进 `Resources`。

## 第一包：图片资产接收、筛选与导入规范

### 目标

先把用户导入的图片做清点、分类和导入设置统一，避免后续在 UI 中“能拖进去但效果不稳定”。

### 重点任务

1. 清点用户本次导入的图片：
   - 文件名
   - 分辨率
   - 是否透明背景
   - 适合做什么（背景 / 面板 / 按钮 / 装饰 / 图标）
2. 按用途分组，至少区分：
   - 大背景图
   - 面板底图 / 边框图
   - 按钮底图
   - 标题装饰图
   - 插画 / 场景氛围图
3. 统一导入设置：
   - `Texture Type = Sprite (2D and UI)`
   - 透明图保留 Alpha
   - UI 图优先 `Mesh Type = Full Rect`
   - `Wrap Mode = Clamp`
   - 按钮 / 面板图根据需要切 `9-slice`
4. 对不适合直接上屏的图片做标记：
   - 文字已烘焙进图
   - 宽高比不适合当前界面
   - 细节过多，可能影响文字可读性

### 通过标准

- 所有新增图片都能说明用途
- 需要 9-slice 的资源已切分完成
- 需要运行时读取的背景图已放到正确 `Resources` 路径

## 第二包：视觉方向与资源映射表冻结

### 目标

在真正改界面之前，先决定“哪张图用在哪个界面”，避免边导图边随意改，导致整体风格散掉。

### 重点任务

1. 先基于现有项目气质确定视觉方向：
   - 项目经理 / 软件项目 / 企业协作 / 轻科技感
   - 保留当前偏蓝灰、深色会议室 UI 的基础氛围，但提升质感
2. 建立一张资源映射表，至少写清：
   - 哪张图给 `MenuScene`
   - 哪张图给 `DialoguePanel`
   - 哪张图给 `DecisionPanel`
   - 哪张图给 `TransitionPanel` / `EndingPanel` / `GameSummaryPanel`
   - 哪些图只用于装饰，不承载信息
3. 明确可读性策略：
   - 背景过花时加遮罩 / 半透明底板
   - 标题区和正文区保持明暗对比
   - 按钮图优先保证点击态和禁用态可分辨

### 通过标准

- 每张核心图片都有明确落点
- 各界面的视觉语言一致，不出现“每个页面像不同项目”的割裂感

## 第三包：高优先级界面视觉升级

### 目标

优先升级答辩和试玩中最常看到的界面，而不是平均用力。

### 第一优先级

1. `MenuScene`
   - 背景图
   - 标题区装饰
   - 主按钮底图与层级
2. `DialoguePanel`
   - 对话背景图
   - 内容底板与文本对比度
   - 地点/角色信息层级
3. `DecisionPanel`
   - 面板底图
   - AI 建议区分层
   - 选项按钮视觉主次

### 第二优先级

4. `TransitionPanel`
5. `EndingPanel`
6. `GameSummaryPanel`

### 第三优先级

7. `CPMGamePanel`
8. `RiskDashboardPanel`
9. `SchedulePanel` / `QuizPanel`（仅在前两级稳定后再补）

### 实施原则

- 静态 UI 优先直接在 `MenuScene` / `GameScene` 的 `Hierarchy / Inspector` 中调整。
- 不为了更换固定背景图而额外写复杂动态造 UI 代码。
- `DialoguePanel` 的地点背景如果要跟地点自动切换，优先复用已有 `Resources.Load<Sprite>()` 路径规则。
- 所有中文显示仍必须使用 `Assets/Fonts/SIMSUN SDF.asset`，不要把文本内容烘焙进图片取代 TMP 文本。

### 通过标准

- 主菜单、对话、决策、转场、结局、总结页至少完成一轮图片升级
- 主按钮与次按钮的视觉主次更明确
- 背景图加入后文字仍清楚可读

## 第四包：一致性与细节收口

### 目标

让导入图片后的界面不只是“贴上图片”，而是形成统一规则。

### 重点任务

1. 统一边角、描边、内边距、阴影或遮罩风格
2. 统一按钮三态：普通 / 高亮 / 禁用
3. 统一标题区、正文区、反馈区、按钮区的视觉层级
4. 检查图片替换后是否出现：
   - 文本压边
   - 九宫格拉伸变形
   - 裁切不正确
   - 射线被遮挡
5. 必要时补少量代码，用于：
   - 默认背景兜底
   - 图像缺失时回退纯色或默认 Sprite
   - 对话地点关键词到图片的序列化映射

### 通过标准

- 主要界面的视觉规则统一
- 没有明显“贴图很好看但按钮点不到 / 文本看不清”的副作用

## 第五包：验证与验收

### 自动化与编译

1. EditMode 全量测试继续通过
2. Unity MCP 编译通过
3. Unity 控制台无新的项目级 `error`

### 手工验证

至少检查：

1. `MenuScene -> 新游戏`
2. `MenuScene -> 继续游戏`
3. `P2 -> P3 -> GameSummaryPanel`
4. `GameSummaryPanel -> 重新开始 / 返回主菜单`
5. `DialoguePanel` 多地点背景切换
6. `DecisionPanel` AI 建议展开、选项按钮、反馈区
7. `1280x720` 与一个更小窗口尺寸下的遮挡/裁切情况

### 产出物

本阶段完成后，至少输出：

1. 修改文件列表
2. 图片资源映射表
3. 新增或修改的图片导入设置说明
4. 自动化测试结果
5. Unity 编译 / 控制台结果
6. 升级后的截图列表
7. 仍待替换或待补的资源缺口清单

## 推荐实施顺序

1. 先接收图片并做用途清点
2. 冻结映射表与视觉方向
3. 先改 `MenuScene`、`DialoguePanel`、`DecisionPanel`
4. 再改 `TransitionPanel`、`EndingPanel`、`GameSummaryPanel`
5. 最后处理小游戏与低优先级面板
6. 全量回归后再整理截图和报告

## 最后提醒

- 本阶段关键词是：`图片导入`、`低风险视觉升级`、`主界面优先`、`静态 UI 优先`、`可读性优先`。
- 判断标准不是“贴图数量越多越好”，而是“最常展示的界面是否更完整、更稳定、更像成品”。
- 如果某张图很好看但会明显伤害文字可读性或按钮可用性，应优先放弃那张图，而不是强行使用。
