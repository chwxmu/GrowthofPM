# Phase 6：有限抛光与答辩演示收口

## 前置条件

- `P0` ~ `P5` 已完成，当前项目已具备从主菜单进入、完整跑通 `P1 -> P2 -> P3 -> GameSummaryPanel` 的主闭环。
- 当前基线已具备：
  - `P2` 两个小游戏、隐藏风险、条件事件、三档结局与 `P2 -> P3` 转场
  - `P3` 的 `dailyIntro / prologue / decision / postDecision / schedule` 主流程接线
  - `GameSummaryPanel` 最终总结页与三项目采纳率 / P3 质量拆分展示
  - 当前 EditMode 自动化基线 `79 passed / 0 failed / 0 skipped`
- `Phase 6` 的定位不是“大而全功能扩展”，而是 **答辩前的有限抛光、演示稳定性提升与关键体验收口**。

## 阶段目标

把项目从“主流程已接通、自动化已覆盖”推进到“关键界面更稳、更清晰、更适合答辩演示”的状态。

本阶段优先级顺序为：

1. 手工回归发现的演示阻塞问题
2. 关键面板的布局与交互清晰度
3. 主路径转场 / 反馈的展示质感
4. 演示安全性与轻量 QoL
5. 仅在前四项稳定后，再考虑低风险音频 / 设置骨架

## 非目标（本阶段不要做）

- 不做新的剧情内容扩写，不回头大改 `P1 / P2 / P3` JSON 剧情结构。
- 不重写 `StoryManager`、`UIManager`、`GameManager` 主架构。
- 不做大规模美术返工、全局 UI 视觉重做、复杂图表系统接入。
- 不把“顺手优化”扩成新的系统工程；任何新增都必须服务于答辩展示稳定性。
- 不在没有资源基础的情况下硬上完整音频资产制作流程。

## 第一包：P2 / P3 手工回归与阻塞项清零

### 目标

把影响答辩演示的流程阻塞问题优先清掉，而不是先做“好看但不关键”的 polish。

### 重点任务

1. 严格执行以下手工回归文档：
   - `Assets/Docs/Tasks/phase-4b-project2-manual-regression-checklist.md`
   - `Assets/Docs/Tasks/phase-5-project3-manual-regression-checklist.md`
2. 对以下问题优先修复：
   - 按钮被遮挡、不可点击、点击区域异常
   - 面板切换后无法继续、交互锁、空白页
   - 保存 / 继续游戏恢复到错误阶段
   - 小游戏重进状态脏、结果页残留、节点或模块无法交互
   - 总结页 / 关键周文本严重遮挡、滚动区失效、按钮不可见
3. 每修一个问题，都补最小必要自动化测试，避免回归。

### 通过标准

- P2 Week 3 / 5 / 9 / 11 / 12 能稳定手工跑通
- P3 Week 1 / 中段周 / Week 12 / 总结页能稳定手工跑通
- 没有“阻断答辩演示”的高优先级缺陷残留

## 第二包：关键面板布局与交互抛光

### 目标

在不大改视觉风格的前提下，让最常被展示的界面更清晰、层级更明确、不同窗口尺寸下更稳。

### 重点面板

- `DecisionPanel`
- `CPMGamePanel`
- `RiskDashboardPanel`
- `TransitionPanel`
- `EndingPanel`
- `GameSummaryPanel`

### 重点任务

1. 统一检查并修正：
   - 标题、正文、反馈区、按钮区的上下层级
   - 长文本换行、滚动区、按钮区与内容区的间距
   - 不同分辨率下的遮挡、重叠、裁切
2. 强化“当前状态可感知性”：
   - 小游戏说明更清楚
   - 当前依赖 / 当前风险结果 / 当前结局信息更显眼
   - 按钮主次关系更明确（主按钮、次按钮、关闭按钮）
3. 保持静态 UI 修改优先走 `Hierarchy / Inspector`，仅在必须时才补脚本约束。
4. 所有中文 TMP 文本继续统一使用 `Assets/Fonts/SIMSUN SDF.asset`。

### 通过标准

- 常用窗口尺寸下关键面板无明显遮挡
- 玩家首次看界面时能迅速理解“下一步该点哪里”
- 不因为布局修正引入新的点击穿透或射线问题

## 第三包：主路径转场与反馈质感提升

### 目标

只对主路径最常见的几个动作做低风险展示增强，让答辩演示观感更完整。

### 建议范围

1. `DOTween` 面板过渡（仅限关键面板，避免全量大改）
   - 面板显示 / 关闭时的轻量淡入或滑入
2. 关键反馈动画
   - 属性变化条或数字变化的轻量过渡
   - AI 建议展开、答题反馈、小游戏成功 / 失败反馈的可感知切换
3. 周推进过渡
   - 周结算后到下一周之间加入短暂、不打断节奏的过渡表现

### 约束

- 只做“看得出来但风险低”的动画，不做复杂序列导演式演出。
- 动画不能影响流程恢复、按钮点击和自动化测试稳定性。
- 若某个动画引发时序风险，优先回退动画而不是强行保留。

### 通过标准

- 主路径面板切换不再显得生硬
- 反馈更易读，但不会拖慢操作节奏
- 控制台无新增 tween 悬挂或空引用报错

## 第四包：演示安全性与轻量 QoL

### 目标

减少答辩现场误操作风险，提升完整试玩的稳定性与可控性。

### 建议任务

1. 键鼠快捷交互收口
   - `Space / Enter` 推进对白
   - `Escape` 关闭当前可关闭面板或打开暂停 / 返回逻辑（若已有入口则复用）
2. 日程与答题的小型防呆
   - 关键按钮在非法状态下禁用
   - 文案提示当前不能执行的原因
3. 轻量演示辅助
   - 更清晰的当前项目 / 当前周展示
   - 如有必要，补一个不打断流程的小型“已自动保存”提示
4. 继续游戏与重开路径复查
   - 主菜单 -> 继续游戏
   - 总结页 -> 重新开始 / 返回主菜单

### 约束

- 不把 QoL 扩成完整设置系统重构。
- 任何新快捷键都不能与现有关键交互冲突。

### 通过标准

- 答辩现场常见误操作不容易直接把流程点死
- 主菜单、继续游戏、重开、返回主菜单路径清楚稳定

## 第五包：可选的低风险音频 / 设置骨架（仅在前四包完成后）

### 目标

若核心演示已经稳定，再补最轻量的“像一个完整游戏”的外围骨架。

### 可选任务

2. 简化设置项
   - `BGM / SFX` 音量
   - 文本速度
   - 使用 `PlayerPrefs` 保存

### 明确说明

- 如果前四包仍有演示阻塞或关键视觉问题，这一包可以直接不做。
- 音频 / 设置属于“锦上添花”，不是本阶段的验收前提。
