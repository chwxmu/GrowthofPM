# 答辩演示路线与截图清单

## 演示目标

- 优先展示“主菜单入口 -> 周流程交互 -> P2 特色机制 -> 最终总结页”这条主线。
- 不把现场时间浪费在从 `P1 Week 1` 重新完整游玩到 `P3 Week 12`。
- 现场演示以稳定、清楚、可解释为优先，详细周数推进和结果统计可由 PPT 材料补足。

## 推荐现场路线

### 路线 A：主展示路线（推荐）

1. `MenuScene` 展示“新游戏 / 继续游戏”入口与主标题。
2. 进入 `GameScene`，展示对话面板与决策面板中“查看AI建议”的交互定义。
3. 用 PPT 或静态图切换展示 `P2` 两个小游戏：`CPMGamePanel`、`RiskDashboardPanel`。
4. 展示 `TransitionPanel` 与 `EndingPanel`，说明项目间继承与阶段性结局。
5. 最后落到 `GameSummaryPanel`，讲述总体采纳率、按项目采纳率、`P3` 质量拆分与研究结论。

### 路线 B：时间紧张时的备用路线

1. 主菜单。
2. 直接展示决策面板与 AI 建议交互。
3. 快速切入 `GameSummaryPanel`，集中讲“研究数据如何记录、如何统计、如何支撑论文”。

## 讲解重点提示

### 1. 周循环

- 用一句话概括：`剧情 -> 决策 -> 日程 -> （可选）答题 -> 结算 -> 自动保存`。
- 不建议在答辩现场把所有周流程逐周点完，而是重点讲每个阶段承担的功能。

### 2. P2 隐藏风险因果链

- `CPMGamePanel` 体现“前置依赖判断失误会带来后续阻塞”。
- `RiskDashboardPanel` 体现“监控纠偏不及时会继续累积隐藏风险”。
- `EndingPanel` 可进一步承接“风险最终会影响项目结局”。

### 3. P3 AI 质量标签

- 重点讲 `good / neutral / bad` 不是装饰字段，而是最终会进入总结页统计。
- 说明玩家是否能识别“坏建议”，是论文分析的重要观察点。

## 演示存档与构建建议

### 演示存档

- 结论：**建议准备，但不是本轮封版阻塞项。**
- 若答辩时间压缩到 `3` 分钟以内，建议现场使用接近 `P2` 或 `P3` 的稳定存档快速进入重点内容。
- 若现场允许完整讲入口与操作，可直接从主菜单开始并辅以 PPT 截图补充后续内容。

### Windows 构建

- 结论：**本轮不强制生成。**
- 当前阶段重点是冻结候选版与论文支撑，不额外扩展构建流程。
- 只有在答辩机器无法使用当前 Unity 编辑器环境时，再补一份 Windows 演示包。

## 本轮取舍说明

- 为避免在已稳定候选版上新增 PlayMode 自动截图脚本，本轮没有引入新的截图自动化工具链。
- 当前采取的收口策略是：
  1. 先完成测试、编译、控制台与研究口径核对；
  2. 再把截图目录、命名规范、画面锚点和讲解路线整理清楚；
  3. 最后由人工在稳定版本上按清单截取最终答辩用图。

- 该取舍更符合 `Phase 7` 的“封版优先、少改优先”目标。
