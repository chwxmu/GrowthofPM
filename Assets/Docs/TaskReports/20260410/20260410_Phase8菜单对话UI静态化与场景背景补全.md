# 20260410 Phase8 菜单对话 UI 静态化与场景背景补全

## 任务背景
- 本轮工作基于已推送的答辩封版基线继续做 UI 收口，不重做既有 Phase8 成果，也不改动周流程、研究埋点、存档口径和项目状态机。
- 用户本轮关注点集中在三个方向：`MenuScene` 中可静态呈现的视觉元素不要继续运行时生成，`DialoguePanel` 的提示文案与人物立绘展示需要进一步收口，以及剧情结束后 `GameScene` 底层界面缺少背景的问题。
- 目标是在保持中文字体规范与现有答辩演示基线稳定的前提下，优先通过场景静态配置和小步脚本修正完成视觉一致性优化，并补齐回归测试。

## 修改文件

- `Assets/Scenes/GameScene.unity`

- `Assets/Tests/Editor/QuizScheduleVisibilityTests.cs`

## 核心逻辑
1. `DecisionPanel` 装饰信息精简
- 移除无实际信息承载作用的 `Watermark` 装饰元素，避免继续占据视觉注意力。
- 保持此前已经确认的答辩封版参数不变，包括 `DescriptionText`、`AIAdviceText`、`FeedbackText` 的高度约束与 `PanelContent` spacing 收口策略。

2. `MenuScene` 静态视觉替换动态生成
- 将主菜单背景图改为场景内静态 `BackgroundPanel`，直接引用夜间办公室背景资源。
- 将背景遮罩 `BackgroundOverlay` 改为场景静态子节点，不再在运行时创建。
- 将主角立绘 `HeroIllustration` 改为场景静态子节点，并固定为右下锚定方式。
- 同步清理 `MenuSceneController` 中原有的动态视觉生成职责，脚本仅保留按钮绑定与继续游戏存档状态刷新。
- 主菜单的 `NewGameButton`、`ContinueGameButton` 已维持无图标状态，不再重复处理。

3. `DialoguePanel` 提示文案与立绘布局收口
- 将 `HintText` 默认提示文案统一为 `点击 / 空格 继续`。
- 去除人物立绘外框装饰：`PortraitFrame` 透明化并移除 `Outline`，只保留立绘本体。
- 下移对话内容区和立绘区域，使其整体更接近封版演示布局。
- 参照 `MenuScene/HeroIllustration` 的参数，将 `PortraitFrame` 改为右下锚定、固定尺寸的静态容器逻辑：
  - `anchorMin/anchorMax = (1, 0)`
  - `pivot = (1, 0)`
  - `anchoredPosition = (-36, 0)`
  - `sizeDelta = (430, 620)`
- 为避免仅容器对齐而图片底边仍悬空，补充 `RefreshPortraitImageLayout(...)`：按精灵宽高比计算显示尺寸，并将 `PortraitImage` 本体以底边为基准对齐到容器底部。
- 修复已有布局二次进入时不会重新应用立绘框参数的问题，确保再次显示对话时也能恢复收口后的布局。

4. `GameScene` 剧情后静态白天背景补全
- 在 `GameCanvas` 根层新增静态背景节点 `GameplayBackground`，放在 `TopStatusBar` 与 `PanelsRoot` 下层之前。
- 该背景直接使用 `Assets/Resources/Backgrounds/Dialogue/OfficeDay.jpg`，覆盖剧情结束后默认只显示纯色相机底板的问题。
- 背景采用全屏拉伸锚定，关闭 `raycastTarget`，确保只提供视觉承载，不影响顶部状态条和各面板交互。

5. 回归测试同步更新
- 更新 `QuizScheduleVisibilityTests`，覆盖以下行为：
  - `DialoguePanel` 提示文案更新为 `点击 / 空格 继续`
  - 人物立绘外框装饰已移除
  - 对话内容区与立绘区下移
  - 立绘框恢复为右下固定锚定参数
  - 立绘图片本体底边对齐到容器底部
  - 既有布局二次显示时也会重新刷新立绘参数
- 更新场景壳层测试：
  - `MenuSceneController_ShouldNotCreateRuntimeMenuVisuals` 确保主菜单视觉不再运行时生成
  - `GameScene_ShouldContainStaticGameplayBackground` 确保剧情结束后的主界面存在静态白天背景

## 测试结果
- Unity 控制台检查：本轮刷新与测试后未出现新的项目级错误；仅观察到 MCP 插件自身的 WebSocket warning，与项目逻辑和 UI 改动无关。
- EditMode 全量回归通过：`91 passed / 0 failed / 0 skipped`。
- 重点验证项：
  - 主菜单静态背景、遮罩、立绘已由场景承载，脚本不再动态创建。
  - `DialoguePanel` 的 `HintText`、立绘去框、下移、底对齐在回归测试中均有覆盖。
  - `GameScene` 在剧情结束后的常驻界面存在静态白天背景，不再只显示纯色底板。

- 本轮未改动周流程状态机、实验埋点、存档行为和项目切换逻辑，全部改动限定在 UI 表现层和对应测试。
- `DialoguePanel` 的背景图切换仍保留既有地点语义解析逻辑；本轮只对剧情结束后的底层常驻界面新增静态背景，不影响对话阶段的背景切换。
