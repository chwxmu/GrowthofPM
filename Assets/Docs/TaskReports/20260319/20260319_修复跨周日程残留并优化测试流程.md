# 任务报告：修复跨周日程残留并优化测试流程

## 任务背景
在手动测试中发现：完成第 1 周日程结算后进入第 2 周，日程面板仍保留第 1 周已选任务，影响周循环准确性。为提升迭代测试效率，本次同步完成了答题面板布局优化与剧情快捷跳过能力，便于快速验证周流程。

## 修改文件
- `Assets/Scripts/UI/SchedulePanel.cs`
- `Assets/Scripts/Managers/StoryManager.cs`
- `Assets/Scripts/UI/DialoguePanel.cs`
- `Assets/Scripts/UI/QuizPanel.cs`
- `Assets/Tests/Editor/Phase2Flow7To12Tests.cs`
- `Assets/Docs/TaskReports/20260319/20260319_修复跨周日程残留并优化测试流程.md`

## 核心逻辑
1. 修复跨周日程残留
- 在 `SchedulePanel` 增加缓存所属周信息（项目号/周数），缓存仅在“同项目同周”条件下可重开。
- 在 `ShowSchedule` 建立缓存时记录当前周上下文；在 `HasCachedSchedule` 中执行周次校验。
- 新增 `ClearCachedSchedule()`，用于清空可用任务、已选任务、回调和缓存标记。
- 在 `StoryManager.StartWeek()` 进入新周时强制调用清缓存，确保跨周一定重置。

2. 增强手动测试效率
- 在 `StoryManager` 增加 `P` 快捷键：仅在 `Prologue/DailyIntro` 阶段生效，直接跳转到决策（若无可用决策则按既有流程进入后续环节）。
- 在 `DialoguePanel` 增加 `ForceCloseWithoutCallback()`，防止跳过剧情时旧回调链误触发。

3. 答题面板可用性优化
- 收紧题目、反馈、选项间距，减少空白占比。
- 将“继续答题”按钮调整到操作区右下角，避免遮挡选项区域。

## 测试结果
1. 自动化测试
- 执行 `EditMode / Phase2Flow7To12Tests`：`16 passed, 0 failed`
- 执行 `EditMode / 全量`：`25 passed, 0 failed`

2. 覆盖要点
- 新增回归用例验证“跨周后从顶部日程入口打开面板时，上一周已选任务会被清空”。
- 已验证剧情跳过快捷键仅在主剧情阶段生效，不影响日程/答题阶段。
