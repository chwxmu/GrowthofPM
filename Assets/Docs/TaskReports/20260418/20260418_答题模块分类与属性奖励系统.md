# 答题模块分类与属性奖励系统

## 任务背景

- 原有答题系统仅支持答对后获得固定精力奖励，无法与四维属性成长形成更明确的联动。
- 本次需求要求将答题系统扩展为五个模块：技术力、管理力、沟通力、抗压力、随机题目。
- 其中前四类模块答对后除获得精力外，还需要额外给予对应属性奖励，并对模块累计奖励设置上限，以便服务后续数值平衡调整。

## 核心逻辑

### 1. 题库增加题型字段

- 在 `QuizQuestionData` 中新增 `questionType` 字段，用于标记每道题所属的模块。
- 题库 JSON 为现有题目补齐了 `techPower`、`managePower`、`commPower`、`stressPower` 四类标签。
- “随机题目”模块不单独维护题库，而是在运行时从全部有效题目中随机抽取。

### 2. 答题奖励从“只加精力”扩展为“精力 + 属性”

- 继续保留答对任意题目获得 `10` 点精力的规则。
- 对于技术力、管理力、沟通力、抗压力四类题目，答对后额外给予 `1` 点对应属性。
- 为防止题库成为无限属性来源，在存档中记录四类题目的累计属性奖励进度，并将每类上限限制为 `80` 点。

### 3. QuizPanel 改为两段式流程

- 玩家点击顶栏答题按钮后，不再直接进入出题界面，而是先进入“答题模块选择”界面。
- 选择题型后，进入现有答题界面进行作答。
- 点击“继续答题”时，保持当前题型继续随机抽题，不回到题型选择界面。
- 在题型选择界面增加提示信息：除随机题目外，其余模块答对可获得 `1` 点对应属性（上限 `80`），答对任意题目均可获得 `10` 点精力。

### 4. 奖励逻辑收口到 GameManager

- 将答题结算逻辑统一集中到 `GameManager.ApplyQuizAnswerRewards(...)`。
- 该方法负责记录答题次数、正确次数、精力奖励、属性奖励以及模块奖励上限判定，并在结算后立即保存。
- `QuizPanel` 只负责展示题型选择、题目内容和奖励反馈文案，不直接处理底层数值规则。

## 测试结果

### 1. Unity EditMode 测试

- 已运行 Unity EditMode 全量测试。
- 最新结果：`99 passed / 0 failed / 0 skipped`

### 2. 新增/更新的验证点

- 答题面板打开后能够先显示题型选择界面。
- 技术力题答对后可同时获得精力和技术力奖励。
- 随机题答对后只会获得精力，不会获得属性奖励。
- 当某一模块累计属性奖励达到 `80` 后，继续答对该模块题目时只发放精力奖励。

## 注意事项

- 当前题库已完成基础题型标注，但四类模块的题量分布并不完全均衡；后续如需更细的平衡体验，可继续补充“抗压力”或“沟通力”题目。
- 题型奖励上限以“单存档累计”方式计算，不按项目重置。
- 旧存档兼容本次改动，新增的答题奖励累计字段会以默认值 `0` 载入。
