# 背景音乐与按钮答题音效接入任务报告

## 任务背景

本次任务基于 `Assets/Resources/Audio/` 下的四个音频资源，为当前项目补齐最小可用的全局音频反馈：

- 菜单与游戏场景共用一条循环背景音乐
- 主流程按钮统一接入点击音效
- `QuizPanel` 答题结果区分正确/错误音效
- 本轮不接入音量设置、静音开关、存档持久化，也不修改小游戏判定逻辑

## 核心逻辑

1. 全局音频管理

- 新增 `GameAudioManager` 单例，继承 `Singleton<T>`，随首次调用自动创建并 `DontDestroyOnLoad`
- 在管理器内部维护一个 BGM `AudioSource` 和一个 SFX `AudioSource`
- 通过 `Resources.Load<AudioClip>()` 缓存以下资源：
  - `Audio/背景音乐`
  - `Audio/按键音效`
  - `Audio/回答正确`
  - `Audio/回答错误`
- `PlaySharedBgm()` 会在同一首 BGM 已播放时直接返回，避免从 `MenuScene` 进入 `GameScene` 时重播

2. 场景入口接入

- `MenuSceneController.Start()` 启动菜单时调用共享 BGM
- `GameManager.InitializeGameSceneRuntime()` 进入玩法主循环前再次调用共享 BGM，用于从其他入口进入时兜底
- 由于 `GameAudioManager` 会复用同一 `AudioSource` 与同一 `AudioClip`，不会造成切场景重启背景音乐

3. 按钮音效接入范围

- 菜单按钮：
  - 新游戏
  - 继续游戏
  - 退出
- 核心流程 UI：
  - `TopStatusBar` 的答题入口、日程入口
  - `DialoguePanel` 的鼠标点击继续
  - `DecisionPanel` 的查看 AI 建议、选项确认、关闭反馈
  - `SchedulePanel` 的添加任务、移除任务、确认、关闭
  - `QuizPanel` 的题型选择、继续、关闭
  - `EndingPanel`、`GameSummaryPanel`、`TransitionPanel` 的跳转按钮
  - `CPMGamePanel`、`RiskDashboardPanel` 的确认/重置/关闭与模块点击
- 所有音效都插在原有业务校验之后，确保无效点击不发声

4. 特殊约束处理

- `DialoguePanel` 通过按钮专用包装方法播放点击音效，键盘快捷推进仍走原来的无声路径
- `QuizPanel.OnClickOption()` 不播放通用按钮音，只根据答题正误播放 `回答正确` 或 `回答错误`
- `CPMGamePanel` 与 `RiskDashboardPanel` 只使用通用点击音，不复用答题对错音效
- `SchedulePanel.OnClickConfirm()` 在 `_onConfirm == null` 时保持静默返回，避免无回调情况下误播音效

## 测试结果

### 资源与脚本导入验证

- 已确认 `Assets/Resources/Audio/` 下四个音频文件均可作为 `Resources` 资源访问
- `GameAudioManager.cs` 已被 Unity 正式识别为 `MonoScript` 并生成 `.meta`

### 编译验证

- 通过 Unity MCP 执行脚本刷新与编译
- 当前 `mcpforunity://editor/state` 显示：
  - `is_compiling = false`
  - `ready_for_tools = true`
- 读取 Console 错误日志结果为 0 条，说明本次音频接入未引入脚本编译错误

### 控制台说明

- 强制刷新过程中出现过一条 MCP WebSocket 初始化警告，来自 MCP 工具包自身连接恢复流程
- 该警告不属于项目脚本错误，最终错误日志已清空

## 注意事项

- 本轮尚未做真实点击回放或录屏式听感验证，当前结论基于资源路径、调用链和 Unity 编译结果
- `GameAudioManager` 采用代码自动创建方式，不依赖场景里预摆放音频对象
- 后续如果需要音量设置、静音、分组混音或存档记忆，建议再引入独立的音频配置数据与 UI 设置面板
