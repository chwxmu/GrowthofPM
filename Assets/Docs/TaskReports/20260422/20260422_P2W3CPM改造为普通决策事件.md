# P2-Week3 CPM 小游戏改造为普通决策事件任务报告

## 任务背景

本次任务将项目二第3周（P2-Week3）的 CPM 连线小游戏改造为普通决策事件，并要求不影响原周流程与 Week5 的条件惩罚逻辑。

改造目标：

- Week3 不再进入 `CPMGamePanel`
- 使用 `DecisionPanel` 展示三选一顺序题
- 继续通过 `cpmCorrect` 控制 Week5 条件事件
- Week3 保持当周无即时数值变化，不改变原平衡口径
- Week3 不计入 AI 采纳率统计口径

## 修改文件

- `Assets/Scripts/Data/StoryData.cs`
- `Assets/Scripts/Managers/StoryManager.cs`
- `Assets/Resources/Data/project2/story.json`

## 核心逻辑

1. 通用可选 flag 写入机制

- 在 `OptionData` 中新增可选字段：
  - `setEventFlagId`
  - `setEventFlagValue`
- 在 `StoryManager.OnDecisionOptionSelected()` 中增加逻辑：
  - 仅当 `setEventFlagId` 非空时，调用 `GameManager.SetEventFlag(setEventFlagId, setEventFlagValue)`
- 该机制对老事件向后兼容：未配置字段的选项不会触发任何新增行为

2. P2-Week3 数据改造

- `decisionEvent` 从 MiniGame 改为普通决策：
  - `isMiniGame: false`
  - `miniGameType: ""`
  - `options` 改为 3 项：`a-b-c-d`、`a-b-d-c`、`b-a-d-c`
- 三个选项均保持：
  - `effects` 全 0
  - `riskChange` 为 0
- 使用新增字段写入 `cpmCorrect`：
  - `a-b-c-d` 写入 `true`
  - 其他两项写入 `false`
- Week5 的 `conditionalEvent.conditionFlag = "cpmCorrect"` 保持不变

3. 统计口径保持

- Week3 `eventId` 设为空字符串，普通决策完成时不会写入 AI 决策记录
- 因此不会改变 AI 采纳率与查看率统计总数
