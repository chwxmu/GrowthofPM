## 核心逻辑

### 1. P2 关键界面静态壳结构回收到场景层级

- 在 `Assets/Scenes/GameScene.unity` 中为以下面板补入固定层级壳结构：
  - `DecisionPanel`
  - `CPMGamePanel`
  - `RiskDashboardPanel`
- 本次优先静态化了固定存在的结构：
  - 标题 / 说明文本
  - AI 建议说明区
  - 状态 / 反馈文本区
  - 固定按钮容器与固定按钮
  - 小游戏的承载容器（如 `Playfield`、`ModulesRoot`）
- 运行时仍保留动态生成的部分：
  - 决策选项按钮列表
  - CPM 连线图形
  - 风险仪表盘的即时报警模块状态

### 2. 面板脚本改为“优先绑定场景静态节点，缺失时再补建”

- `DecisionPanel`、`CPMGamePanel`、`RiskDashboardPanel` 均新增场景节点绑定逻辑：先按固定路径查找已存在节点，再决定是否创建缺失节点。
- 三个面板都补了“对已绑定静态节点重新应用布局/字体/样式默认值”的逻辑，避免只要场景里节点存在但属性不完整时就直接跳过配置。
- 这让后续继续在 `Hierarchy / Inspector` 微调静态 UI 成为可行路径，而不是所有内容都被 `EnsureLayout()` 重新造一遍。

### 3. 周流程 checkpoint 与继续游戏恢复加固

- `StoryManager.ShowDecision()` 现在会在显示决策前就写入 `Decision` checkpoint，确保首个决策阶段也能恢复。
- `StoryManager.ShowSchedulePanel()` 现在会写入 `Schedule` checkpoint，减少继续游戏回到旧阶段的问题。
- `StoryManager.TryShowRiskBasedDialogue()` 现在在展示 Week 11 风险对白前写入 `PostDecision` checkpoint。
- `StoryManager.ApplyConditionalEvent()` 被拆成“效果应用”和“对白展示”两段：
  - 首次进入 Week 5 条件事件时应用惩罚并保存
  - 从 `Conditional` checkpoint 恢复时只重放对白，不重复扣属性/风险
- `TryRestoreSavedFlow()` 的 `PostDecision` 恢复改为重新走 `RunRemainingWeekContentOrSchedule()`，从而让 Week 11 风险对白恢复不再直接跳过。

### 4. CPM 小游戏重连稳定性修复

- `CPMGame.TrySetConnection()` 之前在尝试替换一条边时，会先删除原边，再检查新边是否导致环；如果新边非法，就会把原边也丢掉。
- 现改为：若新连线导致环，则恢复原有出边，避免玩家错误拖拽后把已经连好的正确路径清空。
- 这类修复属于典型“从能跑到可演示”的稳定性加固。

### 5. Phase 4B 文档补齐

- 新增 `Assets/Docs/Tasks/phase-4b-project2-manual-regression-checklist.md`，把 P2 关键周、小游戏重进、继续游戏恢复、三档演示路径拆成可逐项执行的检查清单。
- 本报告记录本次实现、测试与剩余风险，作为 `P2 收口与演示加固` 阶段报告。

## 本次发现并修复的问题

- `DecisionPanel`、`CPMGamePanel`、`RiskDashboardPanel` 之前场景里只有空根节点，固定 UI 结构仍主要依赖运行时生成；现已回收关键壳结构到 `GameScene`。
- 首个普通决策阶段没有提前写入 checkpoint，继续游戏时可能缺少准确恢复锚点；现已在显示决策时保存 `Decision` checkpoint。
- `Schedule` 阶段没有显式写入 checkpoint，继续游戏可能落回旧阶段；现已在显示日程面板时保存。
- Week 5 条件事件恢复会面临“重复扣惩罚”的风险；现已拆分效果应用与对白回放，避免重复结算。
- Week 11 风险对白恢复原先会直接跳到后续逻辑；现已改为恢复时重新走剩余周内容链路。
- CPM 替换连线时，非法新边会吞掉原有合法边；现已改为在失败时保留原连接。
