## 下一阶段建议定位

建议将下一阶段定义为：

`P2：Phase 4C 最终验收与答辩演示准备`

本阶段不再以“继续扩功能”为目标，而是聚焦：

1. P2 关键周人工点击回归
2. P2 三档演示路径实测与路线固化
3. 回归问题的最小必要修复
4. P2 是否达到进入 P3 的准入判断

## 下一阶段目标

### 1. 完成一轮严格人工回归

- 按 `Assets/Docs/Tasks/phase-4b-project2-manual-regression-checklist.md` 逐项执行。
- 重点周：Week 3 / 5 / 9 / 11 / 12。
- 重点边界：小游戏前保存、小游戏阶段保存、条件事件后保存、Week 11 风险对白后保存、Week 12 结局 / 转场页保存。

### 2. 固化三条 P2 演示路径

- 为 `excellent / pass / fail` 各准备一条稳定可复现路线。
- 每条路线至少记录：
  - 关键周选择
  - 小游戏目标表现
  - 预期 `hiddenRisk` 档位
  - 预期 Week 11 文本命中
  - 预期 Week 12 结局

### 3. 只修答辩展示级问题

- 若人工回归发现缺陷，优先级按以下顺序处理：
  1. 会导致流程卡死 / 挂起的问题
  2. 会导致结局错误 / 恢复错误的问题
  3. 会严重影响演示观感的文本遮挡 / 按钮失效 / 状态残留
  4. 数值体验不合理但能通过 JSON 微调解决的问题
- 仍然不推进 `P3` 正式开发，不做 Phase 6 泛化 polish。

### 4. 形成 P3 准入结论

- 如果人工回归通过、三条演示路径至少完成两条实测且剩余风险可接受，则可认为 `P2` 达到进入 `P3` 的前置标准。
- 如果仍存在关键路径不稳、演示路线不可控或恢复体验明显出戏，则继续留在 `P2` 收尾，不进入 `P3`。

## 推荐实施顺序

### 第一包：人工回归执行

1. 先跑 `DecisionPanel` / `CPMGamePanel` / `RiskDashboardPanel` 的布局与交互烟雾。
2. 再按 Week 3 -> Week 5 -> Week 9 -> Week 11 -> Week 12 逐周执行。
3. 每发现一个问题，先记录，再决定是否立即修复。

### 第二包：三条演示路径验证

1. 先验证 `excellent` 路线，作为答辩主展示路径。
2. 再验证 `fail` 路线，确认高风险失败优先级稳定。
3. 最后验证 `pass` 路线，确保中间档不是偶然命中。

### 第三包：最小修复与复测

1. 仅修演示关键问题。
2. 若涉及风险曲线体验，优先调 `JSON`。
3. 修完后至少回归受影响路径，不做无限扩散式修修补补。

### 第四包：准入判断与归档

1. 输出最终手工回归结果。
2. 输出三条路线验证记录。
3. 给出“是否进入 P3”的明确结论及阻塞项。
