## 核心逻辑

### 1. P3 周内时序校准与恢复补齐

- `StoryManager` 新增了面向 P3 的开场编排判断：Project 3 现在按 `dailyIntro -> prologue -> decision` 的顺序接线，避免原先“周内早晨引入剧情跑到主事件后面”的错序感。
- 在 `ShowDailyIntro()`、`ShowPrologue()` 中补齐了 `savedFlowStage` 写入与即时保存，因此继续游戏现在可以正确恢复到：
  - `DailyIntro`
  - `Prologue`
  - `PostDecision`
  - `Schedule`
- `Schedule` 阶段新增“已选任务快照”持久化：`PlayerData.savedScheduleTaskNames` 会在日程面板增删任务时即时写回，继续游戏恢复到 `Schedule` 时可以重建当前选择，而不只是重新打开一个空白日程页。

### 2. AI 统计口径集中到读侧入口

- `GameManager` 新增了统一统计方法，用于给总结页和测试复用：
  - 全局 / 分项目决策数
  - 查看建议数与查看率
  - 跟随建议数与采纳率
  - P3 按 `good / neutral / bad` 的记录数、跟随数与采纳率
- 统计仍以 `aiTrustRecords` 为主数据源，不为总结页额外引入重型存档结构。
- `QuizPanel` 改为通过 `GameManager.RecordQuizAnswer()` 记录答题次数与正确次数，补齐了总结页 `Journey` 区需要的最小统计口径。

### 3. GameSummaryPanel 与 P3 终局接管

- 新增 `Assets/Scripts/UI/GameSummaryPanel.cs`，用于承接 Project 3 最终结局后的总结展示。
- `StoryManager.EndProject()` 现在会在 `currentProject == 3` 且无后续项目时进入 `StoryFlowStage.Summary`，直接展示 `GameSummaryPanel`，而不再停留在普通 `EndingPanel`。
- `GameSummaryPanel` 展示内容包括：
  - 最终结局标题与描述
  - 四维属性总览条
  - `Journey` 统计（已完成周数、总决策数、答题次数、答对题数）
  - AI 总体查看/采纳统计
  - 分项目采纳率条
  - P3 `good / neutral / bad` 质量拆分条
  - 决策时间线色块（绿色=采纳，红色=未采纳，灰色=未查看）
  - `重新开始` / `返回主菜单` 按钮
- `GameScene` 的 `PanelsRoot` 下已新增静态 `GameSummaryPanel` 壳结构，并保存回场景文件。

### 4. 数据 QA 与兼容性收口

- 修正了 `Assets/Resources/Data/project3/story.json` 中 Week 12 的时间文本，将明显冲突的“周三凌晨 4:00 距离上线还有 4 小时”校准为“周五凌晨 0:00 距离上线还有 4 小时”，让最终周的剧情时间线与“周五凌晨上线”设定一致。
- `DataManager.LoadGame()` 已补齐新字段默认值初始化，保证旧存档继续读取时不会因为 `savedScheduleTaskNames` 缺失而空引用。
- 由于 P3 起始周现在会立即写入 `Prologue / DailyIntro` checkpoint，`Project1ClosureTests` 中关于转场后存档阶段的断言同步更新为新语义，避免旧测试和新恢复逻辑冲突。
