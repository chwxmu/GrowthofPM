# P1收口验收与最小修复

## 任务背景

- 本次任务只执行路线图中的 `P1：Phase 3 收口验收`，目标是把 Project 1 收口为稳定完整的第一章。
- 验收重点包括：P1 九周流程、Week 3 双决策、P1 三档结局判定、失败结局阻止进入 P2、成功/合格进入 P2 转场，以及继续游戏后的项目号、周数与关键周内阶段恢复。

## 发现并修复的问题

### 1. 决策后继续游戏会回到错误周内阶段

- 原问题：P0 已经让 `aiTrustRecords` 在决策后即时保存，但当前存档只保存了玩家数值，没有保存“当前周流程走到了哪一步”。
- 直接后果：如果玩家在 Week 3 第一个决策后退出，再继续游戏时会重新从本周开头进入，存在重复触发已保存决策收益的风险。
- 修复方式：为 `PlayerData` 增加最小恢复检查点字段：
  - `savedFlowStage`
  - `savedDecisionStepIndex`
  - `pendingProjectNumber`
- `StoryManager.OnDecisionOptionSelected()` 现在会在 `RecordAIDecision()` 触发即时保存前，先推导并写入“下一步应恢复到的周内阶段”，从而保证保存的数据与恢复目标一致。
- `StoryManager.HandleGameSceneLoaded()` 现在会优先尝试恢复已保存的周内阶段，而不是无条件 `StartWeek()`。

### 2. Week 3 双决策周在继续游戏后无法准确恢复到第二个决策

- 原问题：Week 3 的第二个决策依赖 `_decisionStepIndex` 运行时状态，旧逻辑不会把这个状态写入存档。
- 修复方式：决策后检查点会记录 `savedDecisionStepIndex`；当恢复阶段为 `Decision` 时，`StoryManager` 会按记录的索引直接恢复对应决策。
- 验收结果：继续游戏后可直接回到 `p1_w3_d2`，不会重放第一个决策。

### 3. 失败结局只靠 UI 按钮隐藏阻止进入 P2，缺少流程层保护

- 原问题：`EndingPanel` 虽然会在失败结局隐藏“继续下一个项目”按钮，但 `StoryManager.ContinueToNextProjectFromEnding()` 本身没有按照结局等级拦截，理论上仍可通过代码路径错误推进到 P2。
- 修复方式：在 `StoryManager.ContinueToNextProjectFromEnding()` 中重新计算当前结局；若结果为 `fail`，则直接阻断后续转场逻辑。

### 4. 进入 P2 的时机过早，导致转场页与继续游戏语义不准确

- 原问题：旧逻辑在点击结局页“继续下一个项目”时就直接执行 `AdvanceToNextProject()`，导致：
  - `currentProject` 已提前切到 2
  - 转场页只是展示，不再承担真正的“开始新项目”语义
  - 若玩家在转场页退出再继续，恢复语义不清晰
- 修复方式：
  - `ContinueToNextProjectFromEnding()` 只负责显示转场页，并把 `pendingProjectNumber` 持久化为待启动项目号；
  - 真正更新 `currentProject/currentWeek/energy/hiddenRisk` 的时机改到 `StartCurrentProjectFromTransition()`；
  - 从转场页开始 P2 时，`hiddenRisk` 会按 P1 -> P2 规则重置为 0。

### 5. 结算后仍可能残留旧检查点，影响后续继续游戏

- 原问题：如果不在周结算后清除恢复检查点，继续游戏可能错误回到已完成的决策/日程阶段。
- 修复方式：`StoryManager.OnScheduleComplete()` 在周结算保存前会清空已使用的流程检查点，确保新存档反映的是最新周状态。

## 核心逻辑

### 1. 最小流程检查点模型

- 检查点只记录“继续游戏后该回到哪个核心阶段”，不恢复打字机进度，也不恢复未确认提交的日程勾选缓存。
- 本次支持恢复的关键阶段：
  - `Decision`
  - `Conditional`
  - `PostDecision`
  - `Schedule`
  - `Ending`
  - `Transition`
- 该范围与用户确认的验收口径一致：只保证项目号、周数、关键周内阶段恢复准确。

### 2. P1 结局与转场流程收紧

- P1 结局判定仍沿用 `endings.json` 的正式契约：
  - 优先使用 `excellentThreshold` + `excellentStatThresholds`
  - 否则使用 `passThreshold` + `passStatThresholds`
  - 否则返回 `fail`
- 本次没有重写结局系统，只是补上：
  - `fail` 阻断进入 P2
  - `pass/excellent` 先进入 Transition，再由玩家点击“开始新项目”真正进入 P2

### 3. P1 九周收口验证方式

- 使用真实 `Assets/Resources/Data/project1/story.json` 做结构校验，确认 9 周数据完整、Week 1 三选项存在、Week 3 第二决策存在。
- 通过新增 EditMode 测试模拟 P1 第一套选择路径，逐周推进到 Week 9 Ending，确认主流程从头到尾可落到结局。
- 通过专项测试验证：
  - Week 3 第一个决策后会正确保存“第二个决策”检查点
  - 继续游戏会恢复到第二个决策
  - 结局页与转场页都可作为继续游戏恢复目标

## 剩余风险

- 本次“关键状态恢复准确”的范围按用户确认，只覆盖核心周内阶段，不恢复：
  - 对话打字机播放进度
